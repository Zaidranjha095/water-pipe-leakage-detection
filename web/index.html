How it works

Four steps from a recording to a label

  1. 01

    Audio collection

    Training used one-second field-sensor clips. A phone WAV can be uploaded later as an experimental check; that path is a domain shift, not the measured test set.

  2. 02

    Signal processing

    Audio is resampled to 16 kHz, fixed at 1.0 second, and converted to a 64-bin log-mel spectrogram of shape 1×64×59.

  3. 03

    Deep learning

    A four-block CNN reads that spectrogram. The same weights run in PyTorch and, through ONNX, in this browser.

  4. 04

    Classification

    The model returns logits for leak, no leak, or environmental noise. The page applies softmax and shows every class score.

Dataset

1,000 field clips, three classes

Most leak and no-leak recordings come from an outdoor leakage-detection training base in Dongguan. Environmental noise mixes on-site sound with public background clips. Source: Zenodo 18631450.

The test split is scored once, after the checkpoint is chosen on validation accuracy. Validation accuracy moved during training because the 150-clip val set is small and spectrogram augment is on; the saved weights are the 98.00% peak at epoch 15, not the last epoch. The full archive is fetched by download_dataset.py and is not stored in Git.

What is saved

weights/model.pth stores state_dict, class order, STFT settings, and the mel filterbank. model.py rebuilds the network with build_model(num_classes=3, pretrained=False).

Reference command: python predict.py --audio samples/leak.wav

What the browser runs

The repository file is weights/model.onnx. The live page copies it to downloads/model.onnx at build and runs that alias in ONNX Runtime Web. No audio is uploaded to a server.

Training used class-weighted cross-entropy on an RTX 5070 for 23 epochs with patience 8. Best validation accuracy was 98.00% at epoch 15. Later epochs moved around on the 150-clip val split; that is expected, not a change to the held-out 94.00% test score.

Research

Method, evaluation, and limits

Problem

A leak can run until damage is visible. A one-second microphone clip is a low-cost screening signal, not a utility alarm.

Objective

Train a compact classifier, hold out a test set, publish the checkpoint, and let a browser run the same network.

Preprocessing

Mono audio, 16 kHz, 1.0 s, Hann STFT with n_fft 1024 and hop 256, 64 Slaney mel bands, log power clipped at −80 dB.

Training

Adam at 1e-3, batch 32, inverse-frequency class weights, spectrogram masking and noise, early stopping patience 8.

Evaluation

Seed 42, 70/15/15. Test accuracy 94.00% (141/150), macro F1 93.13%, weighted F1 93.99%.

Limits

Training used field acoustic sensors, not a typical smartphone. Phone upload is experimental and unvalidated. The noise class has 114 clips. A phone recording can be confidently wrong.

About

An academic demonstration

WaterGuard AI is the name of this course page, not a water utility or a company. The work is a Deep Learning semester project: a spectrogram CNN, public weights, and a browser demo.

Stack: PyTorch, ONNX Runtime Web, 16 kHz log-mel features, and a static Vercel site. Optional phone clips with collect_audio.py are a later domain-shift experiment; they were not part of the reported 94.00% test score.
